1: MANY TIMES, WE DEVELOP “TRICKS OF THE TRADE” TO MAKE US MORE ACCURATE AND EFFICIENT. WHAT ARE THE TOP 5 (OR MORE) LESSONS OR “TRICKS OF THE TRADE” THAT YOU’VE LEARNED IN YOUR PRESENT POSITION?

1) Automating Data Retrieval for Efficiency: one  'trick' I've learned is automating data retrieval using APIs. For example, I developed to pull work fatality data from the Bureau of Labor Statistics (BLS) API saves considerable time by batching requests, handling large data sets, and efficiently querying fatality information. By structuring the code to handle multiple queries and split datasets automatically, I reduced the manual effort involved in retrieving data, ensuring the process is both scalable and efficient. This approach can be applied to any API-based data retrieval.

2) Using Web-Based Tools for I/O Standardization: Using web-based tools like the NIOCCS auto-coder for translating free-text industry and occupation data into standardized codes (NAICS, SOC, Census) is an essential trick for ensuring consistency. Automating this process through API calls not only eliminates manual coding errors but also allows large datasets to be processed quickly. This technique is particularly useful when working with occupational health surveillance data, ensuring that data analysis is based on consistent classifications.

3) Applying Natural Language Processing (NLP) for Text Data: Processing and analyzing unstructured text data using NLP techniques has been crucial in improving the accuracy of work-related injury classifications. Techniques like tokenization, stop word removal, and lemmatization help clean and standardize the text data. Additionally, feature extraction using methods like TF-IDF or Count Vectorization feeds the processed text into machine learning models, ensuring that even free-text fields are handled in a structured, reproducible manner. This makes analyzing large volumes of text data more manageable and yields more accurate insights.

4) Utilizing Machine Learning for Accurate Classification: machine learning models such as Logistic Regression, Naïve Bayes, and Support Vector Machines (SVM) have proven to be invaluable for classifying work-related injuries. One trick I’ve learned is to use pipelines in R or Python to automate the preprocessing steps (NLP), feature extraction, and model fitting. This makes the process faster and more reliable, particularly when working with large datasets. Regularly monitoring model performance through metrics like accuracy, precision, and recall ensures that the models remain robust over time.

5) Optimizing Data Processing with Tidyverse: developing strong skills and knowledge of Tidyverse in R has been essential for making data manipulation faster and more efficient. Whether it’s reshaping datasets, filtering, or summarizing data, the Tidyverse suite of tools (like dplyr and purrr) streamlines many repetitive tasks. For example, in the development of the Workforce Estimates Calculation Tool, I used Tidyverse functions to process ACS PUMS data, ensuring that FTE calculations were automated and scalable for various industries. Using srvyr to account for survey weights adds another layer of precision in the calculations.

6) Documenting Workflows for Reproducibility: one of the key lessons I’ve learned is the importance of clear and thorough documentation. Whether it’s a coding workflow for processing syndromic surveillance data or a guide for interacting with APIs like the BLS or NIOCCS, having documentation makes it easier to onboard new team members and ensures continuity. Keeping everything organized—whether in RMarkdown reports, code comments, or detailed workflow documents—has been invaluable for both troubleshooting and collaborating with others.

7) Error Handling and Validation: when working with large datasets and APIs, one essential trick is to build in error-handling mechanisms and data validation checks. Whether it’s handling missing data in NLP preprocessing or validating API responses to ensure the data is complete, these steps are critical in preventing issues later in the analysis. Automating these checks within the code saves time and ensures the accuracy of results before moving forward with analysis.

1) NIOCCS Auto-Coding: Another critical tool is the NIOCCS Auto-coder, which I developed to streamline the process of converting free-text industry and occupation data into standardized codes using the NIOSH Industry and Occupation Computerized Coding System (NIOCCS). This tool automates the web API calls to NIOCCS, processes large datasets efficiently, and returns standardized NAICS and SOC codes. It’s vital to know how to properly structure the API queries and handle the responses to ensure accurate coding of occupational data, which is essential for occupational health studies and surveillance.

2) Workforce Estimates Calculations: One of the key tools I developed is the Workforce Estimates Calculation Tool, which automates the process of extracting and calculating employment estimates from ACS PUMS data. This tool also adjusts for Full-Time Equivalency (FTE) by considering the hours worked per week, providing a more accurate representation of workforce sizes in various industries. It’s essential to understand how to extract the relevant variables, process the data using srvyr, and calculate employment estimates while handling survey weights. 5: DESCRIBE ANY TOOLS THAT YOU CREATED TO HELP YOU PERFORM YOUR JOB MORE EFFICIENTLY. EXAMPLES COULD INCLUDE HOW-TO’S, “CHEAT SHEETS,” JOB AIDS, WORKFLOWS, CHECKLISTS, CALENDARS, AND THE LIKE.

NIOCCS Auto-Coder: I developed an automated tool in R to convert free-text industry and occupation (I/O) data into standardized codes using the NIOSH Industry and Occupation Computerized Coding System (NIOCCS). This tool leverages the NIOCCS Web API to automatically code raw text into standardized NAICS, SOC, and Census codes, eliminating the need for manual coding. This is especially useful for large datasets, such as COVID-19 surveillance data that includes industry and occupation information. The tool not only speeds up the process but also ensures coding accuracy and consistency across datasets. It integrates seamlessly into data processing pipelines and has proven to be essential in occupational health surveillance.

Workforce Estimates (FTE) Calculation Tool: I developed an R-based tool to calculate workforce estimates from the American Community Survey (ACS) Public Use Microdata Sample (PUMS) data and convert these estimates to Full-Time Equivalent (FTE) rates. This tool automates the extraction of relevant variables from the ACS PUMS data (e.g., employment status, industry codes, hours worked per week) and applies statistical methods to calculate employment estimates by industry. Additionally, the tool adjusts for full-time equivalency by standardizing work hours to a 40-hour workweek and multiplying person weights accordingly. It includes functions to calculate margins of error (MOE), relative MOE, and coefficients of variation (CV) to assess the precision of the estimates. This tool is crucial for accurate workforce analysis and for adjusting raw estimates to reflect FTE rates, which is essential for public health and occupational surveillance projects.

Occupational Health Data Processing Checklist: A step-by-step guide for cleaning and processing syndromic surveillance data. This checklist ensures that each data preprocessing task (e.g., handling missing values, categorizing injuries) is completed consistently and accurately.

Machine Learning Workflow Documentation: Detailed instructions for running and maintaining the machine learning models used to classify work-related injuries. This includes model parameters, data preprocessing steps, and tips for interpreting model results.

RMarkdown Reporting Templates: Automated templates in RMarkdown for generating summary reports and visualizations of occupational health data. These templates save time by streamlining the process of creating reports and allow for consistent formatting across different projects.

I rely heavily on tidyverse packages such as dplyr, ggplot2, tidyr, and readr for a variety of tasks:

Data Wrangling: I use dplyr for filtering, selecting, and summarizing large datasets from syndromic surveillance and occupational health sources. It streamlines processes like merging datasets, calculating key statistics, and restructuring data for analysis.

Data Visualization: ggplot2 is my go-to for creating high-quality, customizable visualizations. I frequently create plots to track trends in work-related injuries, syndromic surveillance, and vaccination data. Using ggplot2, I can easily convey insights through bar charts, line graphs, and density plots.

Data Tidying: With tidyr, I ensure that data is in a clean and usable format. Whether it’s pivoting data, separating or combining columns, or handling missing values, tidyr simplifies these tasks.

Data Import: readr makes importing large CSV files efficient, allowing me to quickly load and analyze new data. The fast reading and writing functions are crucial when working with large surveillance datasets.

Cheat Sheets: The tidyverse cheat sheets are excellent resources that provide quick access to function references and examples. They helped me to efficiently apply the most appropriate tidyverse functions for data manipulation, visualization, or reporting tasks. Cheat sheets can be found here: https://www.tidyverse.org/packages/
